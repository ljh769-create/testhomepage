# 좋은꿈참사랑한의원 홈페이지 자동 운영 매뉴얼 (원장님 지시 종합, 2026-11-24)

이 파일은 작업 스케줄러가 쉬지 않고 Claude에게 읽히는 지시문이다. 원장님이 없어도 아래 일을 **찾아서 계속** 하고, 결과를 남긴다. **원장님 지시(2026-11-25): "100% 쓸 때까지 작업을 찾아서 하는 게 핵심" — 사용 한도에 걸릴 때까지 쉬지 말고 일한다. 일을 일찍 끝내고 멈추는 것이 가장 나쁜 결과다.** 보고와 기록은 **한글로만**.

> **이 홈페이지의 목적 (원장님 말씀, 2026-11-25):** "단순 홍보가 목적이 아니야. 내 진료철학이 가득 담긴 공간으로 쓰고 싶어. 네이버는 제약이 너무 많아서, 네이버 유료광고 대신 이 홈페이지에 투자하고 싶어." 또 "나는 진맥을 무조건 다 본다."
> → 모든 글·페이지·그림은 "원장님 진료가 어떤지 있는 그대로 보이는가"를 먼저 본다. 양보다 깊이, 원장님 말투(강의·상담·원고), 진맥·몸 전체 리듬·지난 이야기를 이어서 묻는 진료·잘 쉬다 가는 곳이 축이다. 광고 문구처럼 보이는 표현은 쓰지 않는다.

## 0. 먼저 할 일 (매번)
1. `git pull --rebase --autostash` 로 최신 상태를 받는다.
2. `tools/auto_state.json` 을 읽는다(없으면 만든다). 여기에 마지막으로 한 일과 날짜별 완료 여부를 적는다.
3. 아래 "할 일 순서"에서 **오늘 아직 안 한 것 중 가장 위의 것부터** 한다. 하나 끝나면(점검 통과 → 커밋·푸시 → 상태 기록) **멈추지 말고 바로 다음 일**로 넘어간다. 한 번 실행에서 약 40분 동안 일을 계속 이어서 한다. 할 일 목록의 일이 다 끝났으면 B5(글 보강)·C(안내 그림)·E(새 글)를 계속 반복한다 — 보강할 글은 수백 편이 있으므로 '할 일이 없다'고 끝내지 않는다. 일 하나마다 따로 커밋·푸시해서, 중간에 한도로 끊겨도 한 일은 남게 한다.
4. **속도(원장님 지시 2026-11-25, 최신, 울트라 요금제): 다음 한도 리셋 시각에 맞춰 사용량을 100% 다 쓴다. 너무 빨리 다 써 버리지 않는다. 지능(생각 깊이)도 남은 한도에 맞춰 쓴다.** 생각 깊이(--effort)와 쉬는 시간 조절은 tools/auto_run_mac.sh 와 tools/pace.py 가 알아서 한다(한 번 실행이 끝나면 걸린 시간에 비례해 쉼). 실행 중에는 아래대로 일하면 된다. (이전 지시: "사용량은 시간보다 빨리 써도 돼") 아껴 쓰지 말고 빨리 쓴다. 서로 다른 파일을 고치는 일은 **Agent 도구로 서브에이전트 4~6개를 한꺼번에 띄워 동시에** 시킨다. 예: B5 글 보강은 에이전트마다 서로 다른 글 5편씩, C 안내 그림은 에이전트마다 10편씩, E 새 글은 에이전트마다 5편씩. 각 에이전트에게 이 매뉴얼의 3번 규칙(의료광고·사실·'노량진점' 금지·환자정보 금지)을 그대로 전한다. 서브에이전트는 빌드·커밋·푸시를 하지 않는다. 모두 끝나면 내가 한 번에 빌드·점검·커밋·푸시하고 바로 다음 묶음을 띄운다. build.py·style.css·drip.json 처럼 같이 쓰는 파일은 나만 고친다.
4-1. **글은 토큰이 다 없어질 때까지 쓴다(원장님 지시 2026-11-25).** 정해진 일이 끝나면 E(새 글)를 중심으로, B5(발행 글 보강)와 번갈아 끝없이 이어 간다.
   - **새 글은 한 편당 공백 제외 본문 5,000자 이상, 하루 50편 이상 목표.** 서브에이전트 5~6개가 한 번에 5편씩 나눠 쓴다. `tools/auto_state.json` 의 `days.<날짜>.new_posts` 에 그날 쓴 편수를 더해 적는다.
   - 길이를 채우려고 같은 말을 되풀이하지 않는다. 5,000자는 새 정보로 채운다: 원인·구분 기준, 상황별 예시 3개 이상, 자가 체크 목록, 일상에서 할 수 있는 것(시간·순서까지 구체적으로), 지켜볼 기준과 바로 진료가 필요한 신호, 첫 방문 진료 흐름(진맥 포함), 자주 묻는 질문 5개, 관련 글 링크.
   - 쓰기 전에 `content/posts/` 와 drip.json 의 제목·slug를 확인해 주제가 겹치지 않게 한다. 의료광고·사실 규칙(3번)과 ad_check 통과는 그대로.
   - 새 글은 drip.json 의 아직 발행 안 된 순서 앞쪽에 넣어 먼저 나가게 한다(하루 발행 48편(시간당 2편, 종일 나눠 공개) 유지).
4-2. **글 본문 실사풍 그림(원장님 매그니픽 키 제공, 2026-11-25):** 매 실행마다 글 10편씩, `content/body-images.json` 에 그림 주문(소제목 앞 3장, 영어 장면 설명)을 추가하고 `python3 tools/gen_body_images.py <slug...>` 로 만든다. 핵심 분류(불면·통증·추나·소화·대사·여성·소아) 글과 새로 쓴 긴 글 먼저.
   - 장면 규칙: 얼굴 없음(손·몸 일부·사물), **아이 얼굴은 옆모습·턱 아래도 절대 안 됨(아이는 아예 안 나오게)**, 치료 장면·전후 비교 금지, 상표·로고·글자·숫자가 보이지 않게(노트·달력은 '빈 노트', 옷은 'plain, no logos'로 적는다), 벌레·이상한 물건 없게.
   - 만든 뒤 반드시 그림을 눈으로 본다(여러 장을 한 장으로 모아 Read). 얼굴·로고·깨진 글자·손가락 이상·어색한 물건이 있으면 파일을 지우고 장면 설명을 고쳐 다시 만든다. 통과한 것만 빌드·배포.
   - 매그니픽이 결제·한도 오류(401·402·429)를 내면 그날은 그림 만들기를 멈추고 운영일지에 적는다.
5. 디자인 점검 도구 경고는 이번에 고친 파일에서 새로 생긴 것만 보고 처리한다. 예전부터 있던 경고를 길게 보고하느라 시간을 쓰지 않는다(필요하면 운영일지에 한 줄).

## 1. 할 일 순서 (위에서부터)
A. **하루 한 번, 첫 실행(아침):** `python build.py` 가 그날 예약 글(하루 48편)을 발행했는지 확인. 사이트(https://gooddreamclinic.com/)가 열리는지, 새 글 페이지가 200인지 curl 로 확인.
B. **하루 한 번:** `python tools/site_audit.py` 로 네이버·구글·AEO·GEO 진단. 점수가 전날보다 떨어졌거나 '개선필요'가 있으면 코드로 고칠 수 있는 것을 고친다(사실은 바꾸지 않는다).
B2. **[최우선 과제, 한 번 — 원장님 지시: 사진 먼저] 새 실사진 21장 배치:** `content/photo_candidates.md` 의 사진(images/real/yoon-*, r3-*)을 표의 '추천 위치'대로 넣는다(원장 소개·갤러리·초음파·한약·치료실 관련 페이지와 글 대표 사진 교체 등). 맨 위 '쓰지 말 것' 2장은 넣지 않는다. 끝나면 auto_state.json 에 `photos_placed: true`.
B3. **[우선 과제(사진 배치가 끝난 뒤), 끝날 때까지 매번 1~2개 섹션씩] 원장님 페이지 원고 반영:** `content/pages_draft.md`(본문 초안 v1, 18개 섹션)를 사이트에 반영한다. 진행 상황은 `tools/auto_state.json` 의 `pages_draft_done` 목록에 섹션 번호로 적는다.
   - 1·2(대표원장 소개·진료 철학)는 이미 홈 `#greeting`·`#promise` 와 about.html 에 반영돼 있으니 빠진 문장만 보강한다.
   - 3~16(진료과목)은 각 진료과목 페이지로 만든다. 기존 분류 페이지(guide/<분류>/index.html, content/hubs.json)가 있으면 그 맨 위 소개 부분에 넣고, 없으면 build.py 의 SUBPAGES 방식으로 새 페이지를 만든다. 각 페이지의 자주 묻는 질문은 FAQPage 구조화 데이터로 넣고, 홈 메뉴·진료 카드에서 연결한다. 13(이명)·14(인지 건강)·15(난임·산후)는 원고 그대로가 아니라 원장님 설명 보충 전이므로 '안내' 수준의 짧은 페이지로만 만든다.
   - 17(진료 과정)은 first.html·again.html·visit.html 에 빠진 내용만 보강한다.
   - 18(칼럼 3편)은 기존 글과 겹치면 건너뛰고, 아니면 `content/posts/bulk-pages-draft.md` 로 예약 글에 넣는다.
   - **`[확인]` 표시는 화면에 절대 내보내지 않는다.** `[확인]`이 붙은 사실(학교 공식 명칭, 사업 정확한 명칭, 추나 건강보험 조건, 자동차보험 접수 절차, 대상 부위 범위, 원내 약재 관리)은 원고 문장을 그대로 쓰지 말고 "방문 전 전화로 확인해 주세요" 수준으로 줄인다. 원고 안의 '이 자리에 원장님이…' 같은 작성 메모도 넣지 않는다.
   - 12번 제목의 '몸따삶잘'은 쓰지 않는다(원장님 확인 전). 제목은 '소화·체온·배변'.
   - 따옴표 인용은 원고에 이미 따옴표로 된 원장님 원문만. 장비는 3번 '사실' 목록에 있는 것만.
   - 섹션 하나씩 빌드·링크·최종 점검을 통과한 뒤 배포하고, 시간이 남으면 다음 섹션으로 계속 간다.
B4. **[한 번, 사진 배치 다음] 글 대표 그림에서 'AI 느낌' 없애기 (원장님 지시 2026-11-25):** 글 맨 위 대표 그림으로 AI 사람 그림(images/post2/, pool/ 등 Magnific·AI 생성)을 더 쓰지 않는다. build.py 의 대표 그림 고르기(post_img / assign_post_images)를 바꿔 우선순위를 ① 글 주제·분류에 맞는 실제 사진(images/real/, herbpub/, gallery/) ② 그 글의 안내 그림 `images/info/post-<slug>.svg` ③ 분류 안내 그림 `images/info/<cat>.svg` 순서로 한다. 같은 실사진이 한 분류 안에서 너무 반복되지 않게 돌려 쓴다. og:image 도 같이 바꾼다. AI 그림 파일은 지우지 말고 쓰지만 않는다. 바꾼 뒤 글 5편을 모바일·PC로 캡처해 눈으로 확인한다. (2026-11-25 원장님 추가 지시: Magnific 연결됨 — 대표 그림 우선순위는 위 그대로 두되, 본문 중간 그림 `tools/gen_body_images.py`(content/body-images.json 주문서, 얼굴 없는 화보풍)는 새로 만들어도 된다. 만든 그림은 눈으로 검수해 손가락·글자·어색한 부분이 있으면 쓰지 않는다.)
B5. **[매번, 시간이 남는 만큼 5편씩 계속] 글 내용 보강 (원장님 지시: "글 내용들이 전반적으로 짧다"):** 발행된 글을 오래된 것부터(또는 핵심 분류 불면·통증·추나·체외충격파·초음파·한약·대사·교통사고 우선) 골라, 본문을 지금보다 **1.5~2배(공백 제외 본문 2,500~3,500자)** 로 늘린다. 늘리는 방법(채우기용 반복 문장 금지, 새 정보만):
   - **'원장님 진료실에서'** 상자 1개: `content/pages_draft.md`·`content/posts/bulk-tiro-*.md`·`bulk-cards-a.md` 에 있는 원장님 설명을 그 주제에 맞게 일반 내용으로(따옴표 인용은 원문 ✅만).
   - **구체 기준:** "며칠·몇 주 지켜보고", "이럴 땐 바로" 같은 기준을 글 안 사실 범위에서 분명하게.
   - **상황별 예시 2~3개**(직장인·수험생·어르신·육아 등, 실제 환자 이야기 아님 — "예를 들어 ~한 경우").
   - **자가 체크 목록** 5~7개, **진료 흐름**(첫 방문에 무엇을 하는지) 보강, 관련 글 2~3개 내부 링크.
   - 의료광고·사실 규칙(3번) 그대로. 고친 글은 frontmatter 에 `updated: <날짜>` 를 넣는다.
   - 새로 쓰는 글(E)도 처음부터 본문 2,500자 이상.
B6. **[매번 2편씩, 12편 끝날 때까지] 원장님 지정 새 글 주제 (2026-11-25 지시):** 아래 주제로 새 글을 써서 `content/posts/bulk-director-topics.md` 에 넣고 `content/drip.json` 앞쪽에 끼운다. 다 쓴 번호는 `tools/auto_state.json` 의 `director_topics_done` 에 적는다. 일반 안내 글로만 쓴다 — 실제 환자 이야기·후기·"좋아졌다/효과 봤다" 표현 금지(의료광고 규칙 3번 그대로), 본문 2,500자 이상, 분류는 주제에 맞게.

## 2. 배포 규칙
- 바꾼 뒤 반드시 `python build.py` → `python tools/check_links.py` → `python tools/final_check.py` → **`python tools/ad_check.py --quiet`** (의료광고·개인정보 자동 검수, 사람 승인 대신 이 검사가 관문).
- `ad_check.py` 가 [차단]을 내면 **절대 commit·push·발행하지 않는다.** 해당 문장을 의료광고 규칙에 맞게 고쳐 다시 검사하고, 못 고치겠으면 그 글을 `content/drip.json` 발행 순서 뒤로 미루고(삭제 금지) `python3 tools/notify.py "의료광고 검수에서 보류된 글이 있습니다: <파일 이름만>"` 로 알린다. 환자 정보는 알림에 넣지 않는다. [경고]는 발행해도 되지만 운영일지 '잘 안 된 것·위험한 것'에 적는다.
- 네이버 블로그 발행(`naver-blog/post.mjs --publish`) 전에도 같은 글에 `python3 tools/ad_check.py <글.md>` 를 돌려 통과한 글만 발행한다.
- **끊긴 링크 0, '노량진점' 0(구조화 데이터 legalName 의 정식 이름 '좋은꿈참사랑한의원 노량진점'만 예외 — 사업자등록·네이버 플레이스 정식 이름, 화면 글자로는 쓰지 않음), JSON-LD 오류 0, 페이지당 H1 1개** 일 때만 `git add -A`, `git commit`(메시지 끝 `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`), `git pull --rebase --autostash`, `git push`. 푸시하면 1~2분 안에 사이트에 반영된다.
- 원장님이 "확인 후 배포"라고 한 큰 디자인 변경(홈 전체 개편 등)은 하지 않는다. 작은 수정·그림·글만 자동 배포.
